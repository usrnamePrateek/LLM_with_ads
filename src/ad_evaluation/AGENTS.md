# Agent Instructions: `ad_evaluation` Module

## Purpose
This module is the final evaluation step of the pipeline. It acts as an "LLM-as-a-judge" to evaluate the naturalness, coherence, and disruption of ad placements within the LLM responses.

## Responsibilities
- Masking the generated ad copy to prevent evaluation bias.
- Prompting a large LLM judge to score the placement strictly on structural integration.
- Enforcing structured JSON outputs for the evaluation scores.

## Dependencies
- **Allowed**: `src.common`
- **Forbidden**: Do not depend on `ad_indexing` or `ad_generation`. It reads inputs purely from the CSV files generated by `src.ad_integration`.

## Important Interfaces
- `score_placements.py`: The entry point for the evaluation script.
- `masking.py` (`mask_ad_in_response`): Critical string manipulation function that swaps out the ad content for a placeholder.
- `VllmPlacementJudge`: The LLM generator that handles scoring.
- `PlacementTestingService`: Handles the orchestration, batching, and checkpointing.

## Design Rules
- **Bias Prevention**: The LLM judge must NEVER see the actual ad creative (the headline, description, or CTA). It must only see the `[ad slot]` placeholder. This ensures the judge strictly grades the *placement* quality (e.g., did it interrupt a sentence? Did it match the thematic tone of the surrounding paragraphs?) rather than grading how persuasive the ad text itself is.
- **Strict Parsing**: The LLM output is heavily constrained by JSON schemas (`StructuredOutputsParams`). Ensure the prompt rules in `prompts.py` strongly align with the JSON schema definitions.

## Data Flow
1. Reads `query_ad_positions.csv` (the output from `src.ad_integration`).
2. Applies masking.
3. Batches to `VllmPlacementJudge`.
4. Outputs `placement_scores.csv` via `PlacementScoreCsvRepository`.

## Performance Considerations
- **Checkpointing**: The scoring process takes a long time. The script must remain idempotent and resumable. It accomplishes this by reading `placement_scores.csv` on startup and ignoring IDs that have already been evaluated.
- **Batch Size**: Monitor `JUDGE_BATCH_SIZE`. Too high causes OOM, too low causes severe performance degradation on Llama-70B.
