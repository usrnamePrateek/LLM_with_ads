Project overview · LLM ad placement

Ads in LLM responses that are transparent, effective and efficient

We inject a relevant ad into an LLM's answer to a user query. Every design and evaluation choice in the project serves one of three goals. The tree below maps each goal to how we approach it and how we evaluate it.

Inputs

Datasets

Queries

LMArena dataset

  • Real user prompts from LMArena conversations
  • Cleaned to single-turn queries only
  • Filtered to English queries
Ads

Synthetic ads, LLM-generated

  • 15 high-level topics
  • Each topic split into subtopics
  • Ads generated by an LLM per subtopic, then embedded and indexed
Runtime

System flow at serving time

Codebase

Pipeline modules

Each stage is a module under src/, connected through files on disk. Dots show which goals a stage serves.

  1. ad_generationBuild the data

    Extract and clean LMArena queries; generate synthetic ads by topic and subtopic.

  2. ad_indexingIndex the ads

    Embed ads with BGE-M3 and build the FAISS index.

  3. ad_integrationMatch and inject

    Retrieve the best ad for each query and place it in the LLM response.

  4. ad_evaluationJudge

    LLM-as-a-judge for placement quality, ad preference and identifiability.

  5. speed_comparisonBenchmark latency

    Ad retrieval latency compared with LLM response generation latency.
